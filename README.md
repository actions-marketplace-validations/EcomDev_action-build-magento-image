# Build Magento Data Container Image

A composite GitHub Action that builds (and optionally pushes or loads) multi-architecture Docker container images (`mariadb`, `mysql`, `opensearch`, and `media`) from pre-built Magento data artifacts generated by [`ecomdev/action-build-magento-data-artifact`](https://github.com/EcomDev/action-build-magento-data-artifact).

The resulting images contain pre-initialized database files, OpenSearch indices, or Magento media assets so containers start ready to use in [Testcontainers](https://testcontainers.com/), CI/CD integration pipelines, and local development environments without slow SQL imports or reindexing at startup.

## Overview

During execution, this action:

1. Validates inputs and resolves the artifact source—either reading directly from a local `artifactPath` (such as `output-directory` from `ecomdev/action-build-magento-data-artifact/build-dump`) or downloading a GitHub Actions workflow artifact via [`actions/download-artifact@v8`](https://github.com/actions/download-artifact) by `artifactId` or `artifact` name using `token`.
2. Copies or extracts **only** the archive required for `containerType` into an isolated temporary BuildKit context directory:
   - `mariadb` / `mysql`: `*.sql.gz` / `*.sql` (streamed directly during build-time database initialization)
   - `opensearch`: `search.tgz` → `search/`
   - `media`: `media.tgz` → `media/`
3. Sets up QEMU ([`docker/setup-qemu-action@v4.4.0`](https://github.com/docker/setup-qemu-action)) and Docker Buildx ([`docker/setup-buildx-action@v4.4.1`](https://github.com/docker/setup-buildx-action)) for multi-platform image builds.
4. Logs into the target container registry (`registry`, default `ghcr.io`) via [`docker/login-action@v4.8.0`](https://github.com/docker/login-action) when `push` is enabled.
5. Extracts OCI image tags and labels via [`docker/metadata-action@v6.2.0`](https://github.com/docker/metadata-action).
6. Builds (and optionally pushes or loads) the container image via [`docker/build-push-action@v7.4.0`](https://github.com/docker/build-push-action) using `Dockerfile-<containerType>`, `zstd` OCI layer compression when pushing (`compression` / `compressionLevel`), BuildKit SLSA provenance (`provenance: mode=max` when `load` is `'false'`), optional GitHub Actions cache (`cache`), and build argument `SOURCE_VERSION=<version>`, then cleans up the temporary workspace.

## Supported Container Types

The `containerType` input selects which Dockerfile is built from the artifact data:

| `containerType` | Base Image | Embedded Data | Notes |
| --- | --- | --- | --- |
| `mariadb` | `scratch` *(built from `ghcr.io/wardenenv/mariadb:<version>`)* | `/var/lib/mysql` | Minimal server-only image containing `mariadbd`, required shared libraries, a minimal `/bin/sh` entrypoint, `env`, and pre-initialized `/var/lib/mysql` (no client tools or anonymous `VOLUME`). |
| `mysql` | `scratch` *(built from `ghcr.io/wardenenv/mysql:<version>`)* | `/var/lib/mysql` | Minimal server-only image containing `mysqld`, required shared libraries, a minimal `/bin/sh` entrypoint, `env`, and pre-initialized `/var/lib/mysql` (no `mysql-shell`, client tools, or anonymous `VOLUME`). |
| `opensearch` | `ghcr.io/wardenenv/opensearch:<version>` | `/usr/share/opensearch/data` | Replaces the OpenSearch data directory with the pre-indexed `search/` directory (`opensearch:opensearch`). Gracefully skipped (`skipped: 'true'`) when `version` is omitted/`'none'` or `search.tgz` is absent. |
| `media` | `scratch` | `/` | Minimal data-only image containing unpacked `media/` files with ownership `1000:1000` and permissions `0777`. `version` is optional. |

### Database Runtime Environment Variables (`mariadb` and `mysql`)

Both database container images come pre-configured with default credentials and optional runtime settings:

| Environment Variable | Default | Description |
| --- | --- | --- |
| `MYSQL_DATABASE` | `magento` | Pre-initialized Magento database name. |
| `MYSQL_USER` | `magento` | Pre-configured Magento database user. |
| `MYSQL_PASSWORD` | `magento` | Password for `MYSQL_USER`. |
| `MYSQL_ROOT_PASSWORD` | `magento` | Password for `root`. |
| `MYSQL_ENABLE_BINLOG` | `0` | Set to `1` at container startup to enable binary logging in `ROW` / `FULL` format (`--log-bin=mysql-bin --binlog-format=ROW --binlog-row-image=FULL`). |
| `MYSQL_SERVER_ID` | `1` | Server ID passed via `--server-id` when `MYSQL_ENABLE_BINLOG` is enabled. |

## Expected Data Artifact Contents

Only the archive corresponding to the selected `containerType` is required in the artifact or `artifactPath`. When an artifact is built without `opensearch-version` (no `search.tgz`), `mariadb`, `mysql`, and `media` builds proceed normally and `opensearch` builds skip gracefully with `outputs.skipped == 'true'`:

| File | Used By | Description |
| --- | --- | --- |
| `db.sql.gz` (or `*.sql`) | `mariadb`, `mysql` | Gzip-compressed (or plain) SQL dump of the installed `magento` database. |
| `media.tgz` | `media` | Tarball (`tar -czf`) of Magento's `pub/media` directory (`media/`). |
| `search.tgz` | `opensearch` *(optional)* | Tarball (`tar -czf`) of OpenSearch data (`search/`). When absent, `opensearch` builds are skipped without error. |

## Usage

### Basic Example (Build and Push to GHCR)

```yaml
name: Build Magento Container Images

on:
  workflow_dispatch:
  push:
    branches: [main]

permissions:
  contents: read
  packages: write

jobs:
  build-artifact:
    runs-on: ubuntu-latest
    outputs:
      artifact-id: ${{ steps.build.outputs.artifact-id }}
    steps:
      - name: Build Magento 2.4.9 Data Artifact
        id: build
        uses: ecomdev/action-build-magento-data-artifact@v2.0.0
        with:
          name: magento-2.4.9
          magento-version: '2.4.9'
          php-version: '8.4'
          mariadb-version: '11.8'
          opensearch-version: '3.0'

  build-mariadb-image:
    runs-on: ubuntu-latest
    needs: build-artifact
    steps:
      - name: Build and Push MariaDB Data Image
        uses: ecomdev/action-build-magento-image@v1.0.1
        with:
          artifactId: ${{ needs.build-artifact.outputs.artifact-id }}
          containerType: mariadb
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
          imageName: ${{ github.repository }}/mariadb
          imageTags: type=raw,value=2.4.9
          version: '11.8'
          push: 'true'
```

### Multi-Stage Custom Data Image (Single Job with `artifactPath`)

When customizing a Magento installation using the composable sub-actions in `ecomdev/action-build-magento-data-artifact@v2.0.0`, pass `build-dump`'s `output-directory` directly via `artifactPath` to skip uploading and re-downloading intermediate workflow artifacts:

```yaml
jobs:
  build-custom-images:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write
    steps:
      - uses: actions/checkout@v7

      - name: Initialize Build Environment
        id: init
        uses: ecomdev/action-build-magento-data-artifact/build-init@v2.0.0
        with:
          name: magento-2.4.9-custom
          php-version: '8.4'
          mariadb-version: '11.8'
          opensearch-version: '3.0'

      - name: Create Magento Project
        uses: ecomdev/action-build-magento-data-artifact/build-create-project@v2.0.0
        with:
          config-file: ${{ steps.init.outputs.config-file }}
          magento-version: '2.4.9'
          sample-data: 'true'

      - name: Install Magento
        uses: ecomdev/action-build-magento-data-artifact/build-install@v2.0.0
        with:
          config-file: ${{ steps.init.outputs.config-file }}
          magento-version: '2.4.9'

      - name: Run Custom CLI Commands
        uses: ecomdev/action-build-magento-data-artifact/build-exec@v2.0.0
        with:
          config-file: ${{ steps.init.outputs.config-file }}
          command: bin/magento
          command-arguments: |
            deploy:mode:set
            production
            --skip-compilation

      - name: Reindex Magento
        uses: ecomdev/action-build-magento-data-artifact/build-reindex@v2.0.0
        with:
          config-file: ${{ steps.init.outputs.config-file }}

      - name: Dump Magento Data
        id: dump
        uses: ecomdev/action-build-magento-data-artifact/build-dump@v2.0.0
        with:
          config-file: ${{ steps.init.outputs.config-file }}

      - name: Build and Push MariaDB Image
        uses: ecomdev/action-build-magento-image@v1.0.1
        with:
          artifactPath: ${{ steps.dump.outputs.output-directory }}
          containerType: mariadb
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
          imageName: ${{ github.repository }}/mariadb
          imageTags: type=raw,value=2.4.9-custom
          version: '11.8'
          push: 'true'
```

### End-to-End Matrix Pipeline

Combine [`ecomdev/action-build-magento-matrix`](https://github.com/EcomDev/action-build-magento-matrix), [`ecomdev/action-build-magento-data-artifact`](https://github.com/EcomDev/action-build-magento-data-artifact), and `ecomdev/action-build-magento-image` to automatically build all supported Magento releases and all four container types (`mysql`, `mariadb`, `opensearch`, and `media`):

```yaml
name: Build Magento Data Images

on:
  pull_request:
  push:
    branches: [main]

permissions:
  contents: read

jobs:
  generate-matrix:
    runs-on: ubuntu-latest
    outputs:
      builds: ${{ steps.matrix.outputs.builds }}
      images: ${{ steps.matrix.outputs.images }}
    steps:
      - name: Generate Magento Version Matrix
        id: matrix
        uses: ecomdev/action-build-magento-matrix@v1.0.1
        with:
          months: '12'
          sample-data: 'true'

  build-magento:
    runs-on: ubuntu-latest
    needs: generate-matrix
    strategy:
      fail-fast: false
      matrix:
        include: ${{ fromJson(needs.generate-matrix.outputs.builds) }}
    steps:
      - name: Build Magento Data Artifact (${{ matrix.name }})
        uses: ecomdev/action-build-magento-data-artifact@v2.0.0
        with:
          name: ${{ matrix.name }}
          magento-version: ${{ matrix.magentoVersion }}
          stability: ${{ matrix.stability }}
          mariadb-version: ${{ matrix.mariaDbVersion }}
          opensearch-version: ${{ matrix.openSearchVersion }}
          php-version: ${{ matrix.phpVersion }}
          sample-data: ${{ case(matrix.sampleData, 'true', 'false') }}
          token: ${{ github.token }}

  build-container:
    runs-on: ubuntu-latest
    needs: [generate-matrix, build-magento]
    permissions:
      contents: read
      packages: write
    strategy:
      fail-fast: false
      matrix:
        include: ${{ fromJson(needs.generate-matrix.outputs.images) }}
    steps:
      - name: Build ${{ matrix.containerType }} Image (${{ matrix.artifact }})
        uses: ecomdev/action-build-magento-image@v1.0.1
        with:
          artifact: ${{ matrix.artifact }}
          containerType: ${{ matrix.containerType }}
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
          imageName: ${{ github.repository }}/${{ matrix.containerType }}
          imageTags: ${{ matrix.tag }}
          version: ${{ matrix.version }}
          push: ${{ github.event_name != 'pull_request' }}
          platforms: linux/amd64,linux/arm64
```

## Inputs

One of `artifact`, `artifactId`, or `artifactPath` must be provided.

| Input | Required | Default | Description |
| --- | :---: | --- | --- |
| `artifact` | No* | `''` | Name of the GitHub Actions workflow artifact to download and build the image from. |
| `artifactId` | No* | `''` | ID of the GitHub Actions workflow artifact to download (e.g., `steps.build.outputs.artifact-id`). Takes precedence over `artifact`. |
| `artifactPath` | No* | `''` | Local directory containing exported archive files (e.g., `steps.dump.outputs.output-directory` from `build-dump`). Skips artifact download when set. |
| `containerType` | **Yes** | — | Target container image type to build: `mariadb`, `mysql`, `opensearch`, or `media`. |
| `imageName` | **Yes** | — | Image repository path without the registry hostname (combined as `<registry>/<imageName>`, e.g., `my-org/magento-data/mariadb`). |
| `imageTags` | **Yes** | — | Tag definitions passed to `docker/metadata-action` `tags` input (e.g., `type=raw,value=2.4.9` or newline-separated tag rules). |
| `version` | No | `'none'` | Upstream Warden base image tag passed as the `SOURCE_VERSION` Docker build argument (e.g., `'11.8'`, `'8.4'`, `'3.0'`). Required for `mariadb` and `mysql`; unused for `media`; omitting or setting `'none'` skips `opensearch` builds gracefully. |
| `registry` | No | `ghcr.io` | Target container registry hostname. |
| `username` | No | `''` | Container registry username used when `push` is not `'false'` (e.g., `${{ github.actor }}` for GHCR). |
| `password` | No | `''` | Container registry password/token used when `push` is not `'false'` (e.g., `${{ secrets.GITHUB_TOKEN }}` for GHCR or a Docker Hub access token). |
| `token` | No | `${{ github.token }}` | GitHub token passed as `github-token` to `actions/download-artifact` when downloading workflow artifacts. |
| `push` | No | `'false'` | Push built images and OCI provenance attestations to `registry` when set to any value other than `'false'` (e.g., `'true'`). |
| `load` | No | `'false'` | Load the built single-platform image into the local Docker daemon (`platforms` must specify a single platform such as `linux/amd64`). |
| `cache` | No | `'false'` | Enable GitHub Actions BuildKit layer caching (`type=gha,mode=max`) when set to any value other than `'false'`. |
| `platforms` | No | `linux/amd64,linux/arm64` | Comma-separated list of target OCI platforms for Docker Buildx. |
| `compression` | No | `zstd` | OCI layer compression algorithm used when pushing images (`zstd`, `gzip`, `estargz`, or `uncompressed`). `zstd` and `estargz` enable `oci-mediatypes=true` and `force-compression=true`. |
| `compressionLevel` | No | `'9'` | Compression level used when pushing images (`0`–`22` for `zstd`, `0`–`9` for `gzip`/`estargz`; ignored for `uncompressed`). |

## Outputs

| Output | Description |
| --- | --- |
| `skipped` | `'true'` when the build was skipped (for example, `containerType: opensearch` with no `version` or no `search.tgz` in the artifact), `'false'` otherwise. |
| `digest` | SHA-256 digest of the built container image (`steps.build-and-push.outputs.digest`). |
| `tags` | Generated OCI image tags (`steps.meta.outputs.tags`). |
| `metadata` | Full JSON output generated by `docker/metadata-action` (`steps.meta.outputs.json`). |

## Permissions

Configure job or workflow `permissions` according to whether images are pushed:

| Mode | Required Permissions | Purpose |
| --- | --- | --- |
| Build only (`push: 'false'`) | `contents: read`<br>`packages: read` | Pull `ghcr.io/wardenenv/*` base images and download workflow artifacts. |
| Build & push (`push: 'true'` to `ghcr.io`) | `contents: read`<br>`packages: write` | Push multi-arch images and BuildKit SLSA provenance attestations to GHCR. |

## Requirements

- **Runner Environment**: Linux GitHub Actions runner (such as `ubuntu-latest`) with Docker and `tar` available.
- **Data Source**: Either a workflow artifact (`artifact` / `artifactId`) or a local `artifactPath` containing the archive matching `containerType` (`db.sql.gz` / `*.sql`, `media.tgz`, or `search.tgz`).
